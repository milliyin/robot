# Jetson Nano setup and run commands

cd ~/robot

# Check Python 3.8 and pip
python3.8 --version
python3.8 -m pip --version

# System packages for I2C tools
sudo apt update
sudo apt install -y i2c-tools python3-smbus

# Fix Jetson GPIO/I2C permissions for the current user.
# Reboot after this block, then continue below.
sudo groupadd -f gpio
sudo groupadd -f i2c
sudo usermod -aG gpio,i2c $USER
sudo reboot

# After reboot, confirm your user is in gpio and i2c groups
groups

# Install Python dependencies with Python 3.8
python3.8 -m pip install --upgrade pip==25.0.1
python3.8 -m pip install -r requirements.txt
python3.8 -m pip install -r requirements-jetson.txt

# If Jetson.GPIO still fails, run this directly
python3.8 -m pip install Jetson.GPIO adafruit-blinka adafruit-circuitpython-pca9685

# Check PCA9685 appears on I2C bus.
# You should see 40 in the table.
i2cdetect -y -r 1

# Check Python hardware imports
python3.8 -c "import Jetson.GPIO; import board; import busio; import adafruit_pca9685; print('PCA9685 libs OK')"

# CSI / Raspberry camera quick tests
python3.8 camera_preview.py --snapshot camera_test.jpg
python3.8 camera_preview.py --no-window
python3.8 camera_preview.py

# If the camera image is upside down
python3.8 camera_preview.py --flip 2

# Run simulation only, no hardware
python3.8 main.py --no-gui

# Run direct Jetson -> PCA9685 hardware mode
python3.8 main.py --jetson-pca9685 --no-gui

# Temporary fallback if GPIO/I2C permissions still fail.
# Better long-term fix is group permissions plus reboot above.
sudo -E python3.8 main.py --jetson-pca9685 --no-gui

# If your PCA9685 is not at 0x40, replace the address
python3.8 main.py --jetson-pca9685 --i2c-address 0x40 --no-gui

# Two-way PC <-> Jetson copy/paste website

cd ~/robot

# Start the clipboard bridge on the Jetson
python3.8 copy_paste_app.py --host 0.0.0.0 --port 8787

# In another Jetson terminal, find the Jetson IP address
hostname -I

# On the PC browser, open this, replacing JETSON_IP with the address from hostname -I
http://JETSON_IP:8787

# Optional if firewall is enabled and the PC cannot open the page
sudo ufw allow 8787/tcp

# How to use:
# PC -> Jetson: type/paste text in PC -> Jetson, press Save on PC, open the same website on Jetson, press Copy there.
# Jetson -> PC: type/paste text in Jetson -> PC, press Save on Jetson, open the same website on PC, press Copy there.
# Browser security requires pressing Copy before pasting into another app.



Most likely the app is not running on the Jetson, or 192.168.137.75 is not the Jetson’s active IP.
On the Jetson, run this and keep that terminal open:
cd ~/robot
python3.8 copy_paste_app.py --host 0.0.0.0 --port 8787
You should see something like:
Clipboard bridge running on http://0.0.0.0:8787
On your PC, open http://JETSON_IP:8787
Then open a second Jetson terminal and test locally:
wget -qO- http://127.0.0.1:8787 | head
If that shows HTML, the app is running.
Now check Jetson IP:
hostname -I
Use the IP shown there from your PC browser:
http://192.168.137ip  75:8787
If local Jetson test works but PC still says site cannot be reached, test from PC Command Prompt:
ping 192.168.137.75
If ping fails, PC and Jetson are not talking on the network. If ping works but browser fails, the port is blocked or the app is not listening on 0.0.0.0.
Also check on Jetson:
ss -ltn | grep 8787
You want to see 0.0.0.0:8787, not only 127.0.0.1:8787.


That error means the CSI camera is not opening at the GStreamer/Jetson level yet.
I updated camera_preview.py so next time it prints the full camera pipeline plus the exact test command.
Run this first on Jetson:
sudo systemctl restart nvargus-daemon
python3 camera_preview.py
If it still fails, try lower settings:
python3 camera_preview.py --width 640 --height 480 --display-width 640 --display-height 480 --fps 15
Then test the camera outside Python:
gst-launch-1.0 nvarguscamerasrc sensor-id=0 ! 'video/x-raw(memory:NVMM),width=1280,height=720,framerate=30/1' ! nvvidconv ! 'video/x-raw,format=BGRx' ! videoconvert ! fakesink
If that gst-launch command also fails, the problem is not our Python script. Check these next:
ls /dev/video*
systemctl status nvargus-daemon
Most common physical fix: power off Jetson fully, reseat the ribbon cable, make sure the shiny contacts face the correct direction for the Jetson CSI connector, then boot again.
